# Результаты исправления и переобучения OptimalDrilling

Исправлена утечка будущих наблюдений в категории энергоёмкости и ошибки расчёта
рекомендаций. Обучение и оценка выполнены заново на 427 тестовых скважинах.
Состав тестовых скважин полностью совпадает с предыдущим экспериментом.

## Условия запуска

- Алгоритм: `HistGradientBoostingRegressor` из scikit-learn, 650 итераций,
  learning_rate=0.03, max_leaf_nodes=63, без early stopping и подбора по test.
- LightGBM оставлен как поддерживаемый явно выбираемый backend. В выполненном
  запуске он не использовался: пакет отсутствовал, загрузка из PyPI не проходила
  из-за недоступного DNS.
- Исходных строк: 415 049. После исключения строк без достаточной истории или
  полного будущего target: 290 975 train и 100 190 test.
- Скважин: 1 279 train и 427 test. Пересечения между ними нет.
- Модель скорости обучена на прогнозах вращения из трёх GroupKFold OOF частей.
  Для каждой OOF части калибровка энергоёмкости также обучается без её скважин.
- Обучение и offline-перебор заняли около 166 секунд в проверенном запуске.

## Качество прогноза

| Модель | MAE | RMSE | R² |
| --- | ---: | ---: | ---: |
| Скорость текущей строки | 0,003584 | 0,004689 | 0,256747 |
| Средняя скорость по 12 предыдущим записям | 0,002629 | 0,003634 | 0,553567 |
| Последовательный прогноз скорости | 0,002153 | 0,002957 | 0,704472 |
| Прогноз частоты вращения | 1,987452 | 4,054163 | 0,795813 |

Ошибки скорости выражены в м/с, ошибки частоты вращения — в единицах исходной
телеметрии. Снижение RMSE скорости относительно скользящего среднего составляет
18,64%.

Ранее для скорости сообщались MAE=0,002067, RMSE=0,002795, R²=0,728763.
Сравнение не является изолированной оценкой влияния утечки: одновременно изменены
алгоритм бустинга, target и обучение каскада. Новый target скорости равен
`sum(d_depth[t+1:t+6]) / sum(d_time[t+1:t+6])` (пять следующих записей).

## Исправления и проверки

1. Категории рассчитываются по trailing-медиане доступной истории; медиана всего
   сегмента с будущими строками больше не используется.
2. Нормировка и границы квантилей определяются только по train-скважинам.
3. Физический target скорости согласован с расчётом времени по глубине.
4. При изменении кандидата пересчитываются разности давлений и другие зависимые
   признаки; исторические измерения остаются зафиксированным контекстом.
5. Текущий режим всегда включён в кандидаты, имеет нулевой штраф и выигрывает
   точные равенства. При недостижимой эмпирической области доступен только он.
6. Обучение и движок симулятора используют общие функции; файлы артефактов
   синхронизированы и побайтово совпадают. Источник `dt` везде один — `d_time`.
7. Пройдены 7 автоматических тестов. На всех тестовых интервалах дополнительно
   проверены отсутствие пересечений горизонтов, формула времени, согласованность
   разностей давлений, ограничения ±8% и выбор не хуже текущего режима по score.

Команды повторения:

```bash
python train_advisory.py --backend sklearn
python -m unittest discover -s tests -v
```

Для LightGBM: `python train_advisory.py --backend lightgbm` после установки пакета.
Это создаст отдельный новый результат с соответствующим backend в манифесте.

Движок симулятора проверен на реальных данных без графического интерфейса. Окно
GUI не запускалось, поскольку PySide6 отсутствует в доступном окружении.

Фактическое повышение производительности после изменения давлений пока не
доказано. Для этого необходима независимая проверка отклика на вмешательство или
опытная эксплуатация. В том числе остаются предположения о переносимости модели
на новые режимы и отсутствии неучтённых факторов выбора оператором давлений.
