# OptimalDrilling

**OptimalDrilling** — исследовательский ML-проект для анализа телеметрии карьерного бурения и формирования рекомендаций по режимам работы бурового станка. Проект был выполнен на производственных данных, предоставленных компанией **«Цифра» (Zyfra)**, и направлен на повышение скорости проходки за счёт адаптивного выбора осевого давления и давления вращения с учётом текущей энергоёмкости породы.

## Идея проекта

При бурении карьерных скважин один и тот же режим работы станка может давать разный результат на разных участках скважины: мягкие породы бурятся быстрее, а энергоёмкие участки требуют более точного подбора параметров. Оператор видит текущую телеметрию, но не всегда может одновременно учитывать историю процесса, изменение свойств породы и множество возможных сочетаний управляющих параметров.

В этом проекте была построена рекомендательная система, которая:

- очищает и объединяет телеметрию бурения;
- рассчитывает proxy-показатель энергоёмкости породы по данным станка;
- формирует признаки текущего состояния и динамики скважины;
- прогнозирует ближайший отклик бурового станка;
- перебирает допустимые варианты осевого давления и давления вращения;
- выбирает режим, который по прогнозу должен дать более высокую скорость проходки;
- визуализирует работу модели в desktop-симуляторе.

## Данные

Исходные данные представляют собой телеметрию карьерного бурового станка: глубину, время, скорость проходки, частоту вращения, осевое давление, давление вращения и связанные технические параметры. Давления используются в исходном масштабе датчиков станка и рассматриваются как управляемые параметры режима бурения.

Для учёта неоднородности породы рассчитывается непрерывная proxy-оценка энергоёмкости. Дополнительно она разбивается на четыре квантильных уровня:

- `soft_low_energy` — низкоэнергоёмкие участки;
- `medium_low_energy` — умеренно низкая энергоёмкость;
- `medium_high_energy` — умеренно высокая энергоёмкость;
- `hard_high_energy` — высокоэнергоёмкие участки.

Эти уровни используются для анализа, визуализации и интерпретации результатов. Основная модель при этом работает не только с дискретным уровнем, но и с числовыми признаками текущего состояния процесса.

## Модель и алгоритм

Финальная ML-схема построена в два этапа:

1. модель прогнозирует ближайшую среднюю частоту вращения рабочего органа;
2. модель скорости использует этот прогноз вместе с текущими признаками и оценивает ближайшую среднюю скорость проходки.

В качестве признаков используются текущие управляющие параметры, текущий отклик станка, энергоёмкость, лаги, скользящие статистики и изменения параметров во времени. Для обучения применялась модель **LightGBM**, а подготовка данных и эксперименты выполнены на Python с использованием NumPy, Pandas, SciPy и Scikit-learn.

Рекомендательный алгоритм строит сетку допустимых кандидатов вокруг текущего режима оператора. Для каждого кандидата рассчитывается прогноз скорости и score-функция, которая учитывает не только ожидаемую скорость, но и штрафы за резкие изменения управляющих параметров. Рекомендацией становится кандидат с максимальным значением score.

## Результаты

Offline-проверка на исторических скважинах показала, что модель способна находить режимы с более высокой расчётной скоростью проходки относительно фактического режима оператора. В финальной оценке получен средний взвешенный прирост скорости проходки около **5,5%**.

Анализ по энергетическим профилям показал важную закономерность: модель даёт наибольший выигрыш на более энергоёмких скважинах. На низкоэнергоёмких участках оператор часто уже работает близко к эффективному режиму, поэтому резерв улучшения небольшой. На сложных участках связь между давлениями и скоростью менее очевидна, и модель за счёт истории, энергоёмкости и перебора кандидатов чаще находит более результативное сочетание параметров.

Важно: результат является **offline-оценкой на исторических данных**, а не промышленным A/B-тестом. Проект демонстрирует работоспособность подхода и может рассматриваться как прототип системы поддержки принятия решений для бурения.

## Структура репозитория

```text
OptimalDrilling/
├── datasets/                         # исходные и объединённые данные
├── notebooks/
│   ├── preprocess.ipynb               # очистка и объединение телеметрии
│   ├── rock_energy_segment.ipynb      # расчёт энергоёмкости и surface-data
│   ├── train_drilling_advisory_lp.ipynb # обучение моделей и offline-оценка
│   ├── model_artifacts/               # joblib-модели и JSON-конфиги
│   ├── model_reports/                 # финальные CSV-отчёты
│   └── surface_data/                  # 3D-поверхность для визуализации
├── simulator/                         # desktop replay/advisory симулятор
├── requirements.txt                   # зависимости проекта
└── README.md
```

## Запуск

Установить зависимости:

```bash
python -m venv .venv
source .venv/bin/activate        # Linux/macOS
# .venv\Scripts\activate         # Windows
pip install -r requirements.txt
```

Для воспроизведения пайплайна запустить ноутбуки в порядке:

1. `notebooks/preprocess.ipynb`
2. `notebooks/rock_energy_segment.ipynb`
3. `notebooks/train_drilling_advisory_lp.ipynb`

Для запуска симулятора:

```bash
cd simulator
python run.py
```

Симулятор работает в replay/advisory-режиме: проигрывает историческую скважину, отображает телеметрию, фактическую траекторию оператора, рекомендации модели и единую 3D-поверхность скорости. 3D-поверхность используется только как визуальный фон, а сами рекомендации рассчитываются отдельно обученными LightGBM-моделями.
