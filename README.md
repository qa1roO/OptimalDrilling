# OptimalDrilling

Исследовательский прототип рекомендаций по осевому давлению и давлению вращения
для карьерного бурения. Использует производственную телеметрию, прогноз ближайшего
отклика станка и перебор ограниченной сетки управляющих параметров.

## Методика

- История формируется отдельно по скважинам, в хронологическом порядке.
- Индекс сопротивления бурению рассчитывается по trailing-медиане последних 30
  доступных записей. Нормировка и границы четырёх классов определяются только по
  обучающим скважинам. Индекс является прокси, а не физической MSE или измеренной
  крепостью породы.
- Target скорости на следующих пяти записях равен `sum(d_depth) / sum(d_time)`.
  Частота вращения также усредняется с весами по времени.
- Скважины разделены на train/test с `GroupShuffleSplit`, test_size=0.25, seed=42.
  Модель скорости обучается на GroupKFold OOF прогнозах модели вращения.
- Для рекомендаций пересчитываются все зависимые от кандидата признаки.
  Текущий режим всегда включён как вариант с нулевым штрафом и выигрывает равенства.
- Обучение и симулятор используют общие функции из `drilling_advisory.py`.

## Запуск

```bash
uv sync
uv run python train_advisory.py --backend lightgbm
uv run python -m unittest discover -s tests -v
uv run python simulator/run.py
```

Для явного выбора гистограммного градиентного бустинга scikit-learn:

```bash
uv run python train_advisory.py --backend sklearn
```

Для проверки рекомендаций отдельной моделью, обученной на непересекающихся
скважинах:

```bash
uv run python evaluate_independent.py --backend lightgbm
```

Для исследования числа уровней энергоёмкости:

```bash
uv run python study_energy_classes.py
uv run python study_learned_energy_groups.py
uv run python plot_energy_class_study.py
```

Исследование сравнивает непрерывный E без категории, отсутствие индекса E и
квантильные категории с 2–8 уровнями. Используются три непересекающиеся роли
скважин внутри прежнего train: обучение выбирающей модели, обучение отдельного
оценщика и валидация. Прежний test исключается до построения признаков.
Отдельные проверки разделяют влияние категории как признака и влияние
групповых границ давлений. Дополнительно анализируются смеси Гаусса, silhouette,
устойчивость границ и телеметрические профили групп. Результаты находятся в
`notebooks/model_reports/energy_class_study/`. Основные модели не заменяются.

Эксперимент делит train-скважины на части A и B, сохраняет прежние test-скважины
и проверяет оба направления: A выбирает режим, B оценивает, затем наоборот.
Каждая часть отдельно обучает калибровку энергоёмкости и каскад моделей с OOF.
При оценке рекомендация не изменяется и не отклоняется оценщиком, поэтому
независимый модельный эффект может быть отрицательным. Основной bootstrap
перевыбирает тестовые скважины, объединяя оба направления внутри одной скважины.
Отчёты и отдельные модели сохраняются в
`notebooks/model_reports/independent_evaluation/`; модели симулятора не заменяются.
Это проверка согласованности моделей, а не измерение причинного эффекта на станке.

Backend фиксируется в манифесте и конфигурации модели; автоматической подмены нет.
В первом проверенном запуске использован `sklearn`, поскольку LightGBM отсутствовал
в доступном окружении, а PyPI был недоступен. Версии библиотек сохранены в
`notebooks/model_artifacts/training_manifest.json`.

Обучение читает `datasets/united.csv`, заново создаёт причинно доступные признаки,
сохраняет модели и отчёты и копирует идентичные артефакты в симулятор.
Для пересборки исходного очищенного CSV используется `notebooks/preprocess.ipynb`.
Ноутбук `rock_energy_segment.ipynb` анализирует уже сохранённую train-калибровку;
ноутбук обучения вызывает тот же скрипт, что и командная строка.

## Интерпретация результатов

Проверенный запуск: R² скорости 0.70447, RMSE 0.002957 м/с на 427 тестовых
скважинах. Сравнение модельных сценариев даёт сокращение времени 5.0567%,
эквивалентный прирост скорости 5.3260%. Подробности и ограничения приведены в
`notebooks/model_reports/retraining_results.md`.

Основной показатель рекомендаций — изменение расчётного времени между двумя
модельными сценариями для одних и тех же интервалов: текущие давления и выбранные
давления. Это не измеренный причинный эффект и не результат промышленного A/B-теста.

Сравнение прогнозного времени с фактическим временем оператора сохраняется отдельно
как диагностика ошибки модели. Его нельзя выдавать за эффект оптимизации: такой
показатель может быть ненулевым даже без изменения давлений.

Сценарий с привязкой к фактическому времени использует отношение прогнозных скоростей:
`anchored_time = actual_time * current_prediction / recommendation_prediction`.
При одинаковых давлениях его эффект равен нулю.

Bootstrap-интервал отражает только разброс по тестовым скважинам; он не учитывает
ошибку модели отклика и неопределённость причинного эффекта. Эмпирические границы
давлений не заменяют ограничения безопасности бурового оборудования.

3D-фон симулятора — сглаженная эмпирическая поверхность по train-строкам.
Рекомендации рассчитываются отдельно моделями. Replay не моделирует замкнутое
управление и последующее изменение состояния скважины после вмешательства.
